# Cypher 10.1.1 security boundary - Registered HTTPS Open

The feature is an explicit native Windows action, not a model tool. Only the current text typed into
the resident host can create it. Parsing, app resolution, URL validation, approval and execution all
remain outside Hermes and the local model.

Accepted destinations are at most 2,048 characters, use HTTPS, have no credentials or whitespace,
use the default HTTPS port, and contain one DNS hostname. IP literals and local/reserved suffixes are
rejected. A bare domain receives the fixed `https://` prefix. No query is generated by a model.

The application must already exist in the human-managed Windows app registry. Preparation hashes the
exact executable and binds its identity plus the normalized destination hash into a one-time approval
that expires after 60 seconds. Any app/executable/destination/fingerprint change rejects.

Execution uses `Process.Start` on the revalidated executable, `UseShellExecute=false`, and exactly one
quoted validated HTTPS argument. It does not invoke PowerShell, cmd, a shell association, raw input,
the clipboard, screen capture or UI clicks. Denial, expiry, execution and shutdown discard the URL
from the pending approval object.

The local postcondition proves only that Windows accepted the exact invocation and a registered-app
window or process was observed. It does not prove DNS, TLS, page load, page identity, login state or
rendered content because Cypher deliberately reads none of those surfaces.
