# Cypher 10.21.0 — hands-free voice preview

This is a **validated preview, not a released replacement** for the running 10.20.3 build. The live-microphone acceptance gate below has not yet passed, so the installer has only been run with `-ValidationOnly`.

## Implemented

- The Sherpa wake worker now returns bounded error codes (missing model/dependency, microphone unavailable/overflow, protocol or startup failure). Cypher displays a wake-off state, retries with capped backoff, and reports recovery without logging ambient speech.
- Wake detection and wake-triggered command capture use **one continuous PortAudio microphone stream**. A short, RAM-only pre-roll allows “Cypher, open Brave” as one utterance. A 90 ms local acknowledgement tone plays immediately. A speech-end gate closes the capture; a brief tone alone cannot trigger a command.
- The wake keyword file supports bounded per-phrase score and threshold settings. Defaults remain 1.0 and 0.25 until the user's real voice samples establish better values. The preview worker can now tokenize either the installed GigaSpeech BPE model or Sherpa's newer English-phone lexicon model. No model switch or custom openWakeWord model is bundled without live voice evidence.
- The local Whisper process now stays warm after its first use and handles multiple bounded WAV requests. Audio remains in memory and is cleared after use. Manual MIC still produces an editable draft; wake-triggered commands still auto-send. All existing Windows/file approvals remain in the local route.
- Optional cloud voice can be configured from the tray. It is **off by default** and requires an OpenAI API key plus explicit consent. The key is protected with Windows-user DPAPI. After local wake and speech detection, 16 kHz command chunks are converted to 24 kHz PCM and streamed to the OpenAI `gpt-live-transcribe` WebSocket. Only post-wake chunks are sent; the local pre-roll is not. A failed connection falls back to local Whisper.
- Eligible ordinary questions can use `gpt-6-luna` through the Responses API with `tools: []` and `store: false`. Requests that look like actions continue through Cypher's existing local routing and approval boundary. The cloud answer path cannot execute a Windows/file action.
- Local daily audio/answer usage limits, visible “CLOUD AUDIO”/“CLOUD ANSWER” states, and metadata-only latency events were added. These client-side limits are **not** an account billing cap.
- Read-aloud now substitutes a brief on-screen notice for code blocks, URLs, file paths, long hashes/numbers, and tables. It does not speak those raw details back into the room. This safeguard was prompted by the external voice-layer handoff; its older baseline and local-only/cloud-rejected assumptions were not adopted over the user's current choices.
- The tray now offers **Spoken voice settings**: preview any enabled Windows speech voice, choose one, and adjust speaking speed from -5 to +5. The choice applies to both the acknowledgement and read-aloud, remains local, and is preserved across upgrades. It does not change the recognition model or add cloud speech output.
- **Ctrl+Alt+Space is a voice shortcut**: it acknowledges, records a command without revealing the chat window, auto-sends the transcript, and speaks the answer when available. It does not start a second task while one is active or overwrite an unsent draft. **Ctrl+Win+Alt opens the chat**, as do the tray menu and tray double-click. Approvals reveal the chat for review. The chat shortcut fix was separately installed as 10.20.3 while the rest of 10.21 remains gated.
- After the GitHub comparison, wake capture now prefers the WASAPI copy of the Windows default microphone when it supports its native rate, falling back to the default endpoint otherwise. It converts each native-rate 80 ms block to 16 kHz for Sherpa and Whisper; wake and command capture still share the same open stream. The tray's **Wake microphone settings** list input endpoints by name/API/rate, provide a 3-second signal-only test, and save a name-plus-API choice rather than a reboot-fragile device index. A quiet input is reported after 10 seconds without ending the listener or recording audio. Worker status reports the selected index/rate and distinguishes missing devices or unsupported formats from generic failures.
- The Windows status/stop/upgrade scripts now interpret JSON heartbeat timestamps without converting them through the PC's date locale. On this PC, the old manager falsely reported a live 10.20.0 process as stopped, which also made its stop command a no-op. A regression test exercises live, stale, and future timestamps under an `en-IN` culture. The supervised wake-test helper now has a visible **BEGIN** button, **SPEAK NOW** prompt, and two-minute readiness timeout, so it cannot count an unattended or inaudible-cue run as a voice trial.
- Cloud live transcription now accepts post-wake chunks according to the wake worker's ordered `WAKE`/`CHUNK` protocol, instead of waiting for a later UI-thread acknowledgement. The previous ordering could drop the first chunks of a spoken command when the UI was busy. Each new worker resets its cloud fallback state before reading audio; an old UI callback can no longer undo a streaming failure.
- The microphone selection window stays responsive during its three-second input test. Device-list output is drained while the utility runs, avoiding a possible redirected-pipe stall on PCs with many audio endpoints. The selected input and save control are held steady until the signal-only test finishes.
- The manager's status view now reports whether the wake word is configured, rather than the obsolete hard-coded “Microphone: disabled” line. This is a setting report, not proof that live recognition works.
- The supervised acceptance runner now confirms the user is ready, refuses to interrupt a host reporting active work, checks that the installed process has exited, opens the visible wake test, and restores an initially running host in a `finally` path even if the test fails or is cancelled. The 10.21 host also reports voice recording, speaking, and cloud-answer activity as `working` and defers external stop requests until such activity ends. The currently installed 10.20 host does not yet have that new voice-busy heartbeat guard, so its confirmation dialog asks the user to finish MIC and spoken replies before testing.

## Verification done

The 10.21.0 validation-only installer completed the .NET host build/self-test, the offline wake-model and microphone-format check, Windows host safety tests, worker tests, and voice-worker tests. Further tests cover the real-microphone evaluation helper, PowerShell heartbeat/stop behavior under a non-US date locale, the supervised runner's restoration paths, and the voice picker. Synthetic tests cover native-rate resampling, one-stream wake/command capture, cloud chunk ordering, acknowledgement-tone rejection, bounded keyword tuning, no raw exception leakage, and one warm Whisper model load for multiple requests. A read-only device listing confirmed that the PC exposes the HyperX microphone through MME, DirectSound, WASAPI, and WDM-KS. Earlier audible-tone runs were invalid because the user did not hear the cues. The subsequent **visible, spoken 20-prompt test detected 0/20** with no listener errors; the user confirmed speaking all or most prompts. A five-prompt follow-up reported **0/5 detections, microphone signal on 5/5, no listener errors**. This is a wake-recognition failure, not an unavailable input stream. The installed GigaSpeech model detects its own bundled English sample using both its bundled and Cypher-generated keyword formats. A newer Sherpa English-phone model also detects its own bundled English sample with both formats, and the preview worker now supports its lexicon, but no valid spoken test of that candidate has finished. Its first five-prompt attempt was cancelled before the installed host was paused. The separately updated 10.20.3 app is READY. No live cloud API request has been completed.

## Release gate still open

1. With the intended microphone and normal background applications, test at least 20 spoken wake attempts split between “Cypher” and “Hello Cypher.” Require at least 19 detections. Test a one-utterance command and wake-only/no-command cases. Review the transcript before approving any consequential action.
2. Run at least two hours of background listening. Require no unexpected wake-triggered action and no recurring unavailable events. Compare the new sanitized error codes with the previous 185 generic wake failures if any recur.
3. Compare local and cloud transcription on the **same consented spoken commands**, then measure wake-to-acknowledgement, speech-end-to-transcript, and transcript-to-first-spoken-answer from metadata events. Verify cloud failure falls back locally. This step needs the user's API key and incurs possible charges.
4. Install 10.21.0 only after these checks pass. Until then, 10.20.3 remains the installed build.

### Safe preliminary microphone check

From this preview directory, run `scripts/run_wake_acceptance_windows.py attempts` with a Windows Python that includes Tkinter. Confirm that no MIC recording, spoken reply, or other task is active; then click **BEGIN** in the visible test window. The runner pauses an idle installed host, verifies it is gone, alternates 20 visible “Cypher” and “Hello Cypher” prompts, then restarts and verifies an initially running host. For a two-hour background check, use `scripts/run_wake_acceptance_windows.py background`; **do not say the wake phrase** during that check. The lower-level `evaluate_wake_microphone.py` helper remains available only after the installed listener has been independently paused and verified. Neither script transcribes, dispatches, or saves captured audio. These preliminary checks cannot prove end-to-end UI auto-send, spoken answers, or approvals; those still need a supervised integrated check.

To compare a staged model without changing installed settings, pass `--candidate-model <unpacked-model-directory>` to the supervised runner. The candidate must be tested with the user's voice and the same 19/20 gate before it can replace the installed model. The sample-only model check is `scripts/check_wake_model_sample.py --model-dir <unpacked-model-directory>`; it tests decoder and keyword-file compatibility, **not** wake accuracy.

## Known limits

- Manual MIC still uses the earlier Windows recorder; the new same-stream guarantee applies to **wake-triggered** commands. Both normally target the selected Windows default microphone, but manual MIC can differ on unusual multi-device setups.
- The first local Whisper request still loads the model; subsequent requests reuse it. A cold start may remain slow.
- Local daily limits do not replace OpenAI account-level budget controls. API data is not used for training by default, but standard abuse-monitoring retention may apply. See [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data) and [pricing](https://developers.openai.com/api/docs/pricing).
- No sample recordings are stored by default. Any custom wake-model evaluation needs separately consented, representative recordings.
- Voice barge-in and sentence-by-sentence streaming TTS are not yet implemented. Wake listening is suspended during Cypher's speech to avoid echo-triggered actions. Stop still works via the UI, but spoken interruption while Cypher is talking needs echo-safe design and testing.
